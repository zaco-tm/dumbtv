# The ports: what the prototype has, and what the app has

The prototype is the design and this app is the product, so a component is ported when its
behaviour is matched, not when its code looks similar. The table that says what each one has to
match is [docs/superpowers/averagetv-parity.md](../../../docs/superpowers/averagetv-parity.md); this
file is the app's side of it: what exists, and what is still to come.

## The components

| In the prototype | In the app | State |
|---|---|---|
| `@charcoal/line-sidebar` (`src/components/ui/line-sidebar.tsx`) | `src/ui/charcoal/Rail.tsx` | **Done (task 7).** Always open, as on a television: 220px wide, 60px rows, 26px icons, 22px labels, the items at the top and the gear and the children's face at the bottom. The active item's line is in ember with the theme's glow, and the spring is stiffness 360 / damping 34 — with the system's reduced motion, no animation at all. Measured by the numbers, not by a screenshot: the television is off. |
| `@charcoal/rating` (`src/components/ui/rating.tsx`) | `src/ui/charcoal/Rating.tsx` | **Done (task 7).** Five stars, the filled ones in ember, the empty one outlined and muted. Always read-only: it never takes the focus and it never answers the remote. The star is the prototype's own path, not lucide's. |
| `@charcoal/carousel` (`src/components/ui/carousel.tsx`) | — | **Not ported, and it will not be.** The sketch has no carousel: the Favorites row and the ranked list are driven by the focus, not by dragging. It stays in the prototype because it is free there. |
| The theme's card and button primitives | `src/ui/charcoal/Card.tsx`, `Button.tsx` | **Done (task 7).** The surface colours, the radii and the ring, and only what the screen uses: the card is the app tiles' and the posters' surface, the button is the focusable tile. |
| The theme's CSS variables | `src/ui/charcoal/tokens.ts` | **Done.** Generated by `tools/gen-tokens.mjs` from `prototype/src/index.css`; never copied by hand. |
| The theme's fonts | `src/ui/charcoal/tokens.ts`, `src/ui/charcoal/theme.ts` | **Done (task 7).** `variant/assets/fonts/InterVariable.ttf` is copied into `android/app/src/main/assets/fonts/`. The token keeps the prototype's CSS family name ('Inter Variable'); Android finds a font by the name of the file, so the app uses the font's own PostScript name, `InterVariable` (`src/ui/charcoal/theme.ts`). |

## The parts that are not components

| In the prototype | In the app | State |
|---|---|---|
| `src/lib/tvFocus.ts` — the grid focus model | `src/ui/focus.ts` (the model), `src/ui/useFocusGrid.ts` (the plumbing) | **Done (task 7).** The model is a pure function over a list of positions, in TypeScript, with no React and no React Native in the file — so jest proves it with no device. The movements the prototype was measured against are the movements `__tests__/focus.test.ts` proves: right from the rail enters the page at its top-left (right from Streaming lands on the first app, not the seventh; right from Gaming on the first console, not a game), down from a console walks the games, left from the content returns to the rail item of the page you are on, and up and down stay inside whichever list you are in. The focus is moved with the `focus` command, and React Native's own flags for keys and for the imperative focus are turned on in `ReactFlags.kt`. |
| `src/lib/fit.ts` — the 1920×1080 stage | `src/ui/stage.ts` | **Done (task 7).** The screen is the stage: there is no scaling, and a stage pixel is a dp divided by the density, so the prototype's numbers are the television's pixels whichever way the screen is set up. |
| `src/data/mock.ts` | the native modules | The modules answer; the data layer is task 8's work. `src/data/mock.ts` is the prototype's mock data, marked as the placeholder it is. |
| `src/sections/*` | `src/screens/Home.tsx` | **Done (task 7).** The greeting, the Favorites row, and the Trending feature with its ranked list, with the prototype's numbers: 72px greeting, 32px section titles, 22px labels, 176px tiles, 104px app boxes, a 340px feature. |

## The native modules

The JavaScript's way into Android. The shape is already the final one; what each stub does and what
is still missing is written down in the module's own source file.

| Module | What it answers | Now |
|---|---|---|
| `parent_pin` | `check(pin)`, `set(pin)` | **Real.** The salted SHA-256 hash in the `parent_pin` file, in the format the Java app uses. |
| `home_mode` | `isHome()`, `setHome(on)`, `refresh()` | A stub. `isHome()` asks the system who holds the HOME role; `setHome()` only records the request, because the real switch needs the television's own ADB (task 8). |
| `inputs` | `list()` | A stub. It reads the displays Android reports, which on a television are the HDMI inputs. The input screen itself is task 8's work. |
| `sleep` | `start(minutes)`, `cancel()` | A stub. It writes the end of the timer into the settings file, in the Java app's keys. The blanking is task 8's work. |
| `prefs` | `get(file, key)`, `set(file, key, value)` | **Real**, for the `settings` and `home-ui` files. The PIN's file is not reachable from here. |
| `night` | `isNight()` | A stub with the Java app's rule: the theme has the last word, and without sun times it is night from 18:00 to 06:00. |
